# v0.4.0

`read` now keeps a page that isn't citable out of an agent's answer, as `search` already did.
By default it returns the page's owner and why the page is excluded, not its text. Found by
benchmark round 2, where an agent took an id from search's `excluded`, read the page, and
repeated a stale runbook's steps.

## Breaking: `read` leaves out the text of a page that isn't citable

- **What changes:** `read` of a page that is a draft, deprecated, past its review date or
  unowned returns its metadata, `flags`, `gate_reason` and `owner_team`, with no `content`.
  A `note` says the text was left out and tells the agent to name the owning team instead.
  A citable page, one that's due soon included, is read as before.
- **To get the text,** for updating the page: `read` with `include_stale: true`, the flag
  `search` takes. The page is labelled as before.
- **For a client that relied on `read` returning a stale page's text:** pass
  `include_stale: true`.
- **`policy.include_stale: denied`** now covers `read` too. The flag is then ignored, and the
  note says it's the policy.
- **The polish prompt and the polish, verify and update-after-incident skills** pass
  `include_stale: true`, since they update the page.
- **The audit log** records a read that left the text out under `excluded`, as it does for
  search, and a read with the text under `returned`. It records `include_stale` too. The
  usage log still counts every read: the digest's "most read by agents" is what agents asked
  for.
- **What this doesn't cover:**
  - `ui_page`, the web app's page view on `docsworth serve`, shows every visible page's text,
    for a person fixing it. Any client holding the serve token can call it.
  - A `mirror:` id is read with its text, as context.

## The Claude Code plugin

- **It runs exactly this release:** `npx -y @docsworth/cli@0.4.0 mcp`, no longer the `^0.3`
  range. Anthropic's plugin directory refuses a launcher that runs a range, and a range would
  let a later publish reach every plugin user before the plugin naming it was reviewed. A
  plugin update now brings each CLI release, and the release guard refuses a release whose
  launcher runs any other version.
- **Its own README,** `plugin/README.md`: what it adds and how to set it up, then everything it
  runs, reads, writes and sends, a privacy policy and the licence. The directory shows it as
  the listing.
- **Its manifest** gains a display name, homepage and repository. Its author, and the
  marketplace's owner, read "Docsworth".
- **`DOCSWORTH_BIN`** still runs your own installed CLI instead, which is how pro is used.

## `init --ci` and the 0.4 range

- **`docsworth init --ci`** now writes a workflow that fetches `@docsworth/cli@^0.4`.
- **A workflow written by 0.3 keeps fetching `^0.3`,** which lints the same format (format
  version 1, unchanged), so nothing breaks. To move it to 0.4, change the range in
  `.github/workflows/knowledge.yml`, or delete that file and run `docsworth init --ci` again.

## Pro

- **Host API 4.** `KnowledgeService.read` changed meaning, so the contract between the CLI and
  pro moves from 3 to 4. Install pro 0.4 with CLI 0.4: the CLI refuses a pro built for 3, and
  says so.

## The benchmark

- **Not the same system as before:** the server's instructions and `read`'s description
  changed, so bench rounds from before this release and after it can't be compared directly.
