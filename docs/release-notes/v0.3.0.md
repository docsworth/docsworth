# v0.3.0

The release for teams that already have docs. `docsworth adopt` turns an existing docs tree,
a Docusaurus site say, into Docsworth pages without moving a URL, and `docsworth verify`
makes them citable once someone has read them. Redaction now reads links as a docs site
serves them. `serve` and the web app hold up at a real team's size.

## Adopting existing docs

- **`docsworth adopt [dir]`** gives pages the frontmatter they lack, as drafts, so none is
  citable until someone verifies it:
  - **`id`:** the page's file name, so no Docusaurus URL moves. A category index or a
    clash is reported for an id set by hand.
  - **The other fields:** the title from the first heading, the owner from CODEOWNERS or
    `--team`, `last_verified` from git.
  - **Links:** route links become relative `.md` links, read as CommonMark reads them. A
    link it can't place is left as written and listed.
  - **Site-generator keys** (`sidebar_position`, say) go in a config list,
    `frontmatter.extra_fields`, instead of drawing a warning on every page.

  It writes only inside the repo and nothing to git, and `--dry-run` shows what it would
  do.
- **`docsworth verify <paths>`** marks pages canonical, verified today, and leaves the rest
  of each page's frontmatter as it was, byte for byte.
- **Lint reads links as CommonMark does** (commonmark.js): a link in code isn't one, and a
  reference counts through its definition. Under the knowledge root a link must name a page
  or an attachment, not a directory or a route.
- **`static_dirs`**: the directories a docs site serves at its root (Docusaurus's
  `static/`). Lint reads `/img/x.png` there, and adopt says what to list.
- **On Hermes Agent's 333 Docusaurus pages**, adopt took lint from 1,934 errors to 4, the
  site's own broken links. Every one of 1,213 independently inventoried links still names
  the same file.

## Who sees what

- **Routes, as a docs site serves them.** A link to a page you can't see reads
  `[restricted page]` when it reaches the page by its route, too:
  - by its `slug`;
  - by an `id` other than its file name;
  - by its path without number prefixes;
  - by its file's stem.

  Where two pages share a route, hidden wins.
- **A link without an extension that names nothing** (no page, file or directory in the
  repo) reads `[restricted page]` for everyone. So a hidden page whose route can't be read
  never shows its label. Broken links of that shape, and links to a docs site's generated
  pages (`/category/…`), read that way too.
- **`site_url`**: with it set, a URL on the docs site counts as the route it names,
  wherever it's written. A route mentioned in plain text, not as a link, is served as
  written.
- **Where a browser goes.** Each link is also read as a browser resolves it. That fixed
  leaks: a link written with an escaped backslash or slash (`zz&bsol;../../index.md`,
  `zz%2F../../index.md`) could reach a hidden page while it looked like a visible one.
- **A reference goes with its definition.** A definition removed for a hidden page takes
  its references with it, label and text, in quotes and lists too, as CommonMark matches
  labels. A reference inside a quote used to show its label.
- **Fuzzed** against CommonMark's reference parser, an HTML5 parser, and an independent
  model of Docusaurus's routing: 0 leaks in 240,000 texts. The same fuzz found 9,308 leaks
  in v0.2.0's redaction on the paths corpus.
- **Checked against a real Docusaurus build.** Hermes Agent's site was built with
  Docusaurus 3.9.2. Of its 335 docs, all 334 `.md` pages are served at the route
  Docsworth reads them at. The other one is an `.mdx` file, which Docsworth doesn't load
  as a page. A copy with test pages for each rule agreed too: `slug` and `id`, number and
  version prefixes, and category indexes, which Docusaurus tells by the names as written.

## Search and the web app

- **Snippets show what the page shows**, from one GFM parse. A link the 240-character cut
  went through shows as its text.
- **Tables** render.
- **At a real team's size**, checked on 3,000 pages: one load per server, sessions
  reclaimed, and a link graph you can draw.
- **The overview** lists the first 20 stale and due-soon pages and shows all on request.
  A deprecated page isn't counted as past review. It says how many files couldn't be read
  as pages, without naming them.
- **A team's page** lists what needs review first, and links its graph.
- **When the server is gone**, the app names the server that didn't answer, instead of
  "Failed to fetch".

## The extension

- **Save a page or a selection** to the knowledge base. The tab is turned into markdown
  where it is, and the side panel shows it for review. Nothing is written until you open
  the draft PR.

## Packaging

- `@docsworth/cli` 0.3.0, installed as `@docsworth/cli@^0.3`. The plugin and
  `docsworth init --ci` fetch that range.
- Docsworth pro 0.3.0 pins this CLI. The contract between the two (the host API) is
  unchanged, at 3.

## The format

- **New config keys:** `frontmatter.extra_fields`, `static_dirs`, `site_url`.
- **`knowledge_root` is checked:** a directory in the repo, not `.`, `..`, absolute, or
  in `.git` or `.knowledge`.
- **Inside the knowledge root**, a directory whose name starts with a dot is skipped, as
  the loader always did.

## Not verified against the real thing

- **Routes** are checked against one real Docusaurus build (3.9.2, Hermes Agent's site
  with test pages added): not other versions, other sites' configurations (a
  `routeBasePath` other than `/`, `trailingSlash`), or other site generators.
- **`docsworth adopt`** was run on one real site, Hermes Agent's 333 Docusaurus pages.
- **The extension** is unchanged in how it's installed: built from `packages/extension`,
  loaded unpacked, not in a store.
