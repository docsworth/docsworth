# v0.3.3

Day one with existing docs: adopted pages get the dates their content really has, and a
queue says which drafts to read and verify first. Found by setting Docsworth up on two
real projects, as a customer would.

## Adopting docs copied from other repos

- **`docsworth adopt --dates-from <repo>`,** once for each repo the pages were copied
  from. A copy has no history in the knowledge repo, so until now every copied page was
  dated the day of the copy. Now a page gets the newest commit, in those repos' history,
  that introduced its exact content, whatever the file is called there. Failing that, the
  newest commit with that content in the knowledge repo; failing both, today, and adopt
  lists the page.
- **Adopt reports** how many pages each repo dated, and each page dated today.
- **A path that isn't a git repository, or one with no commits,** is refused before
  anything is written.
- **What won't match:** a copy edited before adopt ran, content behind a git filter other
  than line endings (Git LFS, say), and content that appeared only in a merge's conflict
  resolution. A file moved there without edits counts as changed when it moved.
- Without `--dates-from`, adopt dates pages exactly as before, and its output, text and
  `--json`, is unchanged.

## The verify queue

- **`docsworth drafts [dir]`** lists the drafts, the newest content first, with each one's
  date, review state, owner, path and title: a page changed last week is likelier to be
  right than one untouched for a year. `--owner-team` narrows it to one team's pages, and
  `--json` prints `{ id, title, path, owner_team, changed, sla_state }` for each.

## Local knowledge repos

- **In a git repository with no remote, `verify` and `adopt` say to commit,** not to open
  a pull request there's nowhere to open. With a remote, or outside git, they say what
  they said before.
