# v0.2.0

The release that makes the knowledge server ready for a team's security review:
governance an admin can show, edits agents can make safely, and wiki pages agents can
read without citing them. People get a way in too: a web app and a browser extension, both
talking to a server on their own machine.

## Governance

- **Audit log.** One event per tool call, recorded where the call arrives and attributed
  to a person. Writes record their intent before they reach GitHub. Events are kept in
  files with a retention period, or shipped to a SIEM with a bounded queue (the SIEM
  sink is in the paid tier). Page content, hidden page ids and search text (unless you
  turn it on) are never recorded.
- **Org policy.** A `policy:` block names the admin team, allows each tool to the teams
  you choose, can switch writes off, and can require a person's approval for every
  call. Lint checks that `CODEOWNERS` gives the config to the admin team.
- **Identity.** Installation tokens, which act for no person, are refused. A token that
  isn't authorized for the org's SAML single sign-on fails with the link to authorize
  it. Team membership is cached for a window you set (`identity_cache_seconds`).
- **Retention and deletion.** Every store the server writes is listed with its owner and
  how it's deleted (`docs/enterprise/data-inventory.md`). `mirror-purge` removes a
  mirror's files.
- **Admin reports** (paid tier): an access review of who can see, verify and approve
  each page, and a usage report from the audit files.

## Who sees what

- **Links to pages you can't see** read `[restricted page]` in every form a reader
  resolves: markdown links of any shape, reference definitions, HTML attributes (`href`,
  `src`, `srcset`, an iframe's `srcdoc`, a refresh, and the rest), URLs parsed as a
  browser parses them, paths in text and code, and as they render, with markup or
  comments inside. A relative link, or a GitHub URL into the repo, to a path that is no
  page fails closed too: a page on another branch never loads, so its ACL can't be read.
  Fuzzed against CommonMark's reference parser and an HTML5 parser: 0 leaks in 480,000
  texts.
- **`supersedes`** in `read` lists only pages the caller could look up.

## Editing

- **Polish.** `propose_edit` with `polish: true` lets an agent restructure and reword a
  page as a PR. The server refuses the polish if it changes a code block, inline code, a
  link, a number with its unit, a negation word or a task's box. The check reads pages
  as CommonMark does. It has been fuzzed against CommonMark's reference parser, with no
  miss in 1.5 million mutated pages. It's structural, so owners still read every polish
  PR. A slash command and a skill drive it from Claude Code.
- **Concurrent proposals** get their own branches, even on the same page in the same
  second.
- **`draft_page`**, a seventh tool, adds a page as a draft PR. The server picks the id and
  the file name (`<prefix>-<slug>-<12 hex>`), so the tool can't be aimed at a hidden page
  to learn it exists. Before anything is written, it checks the policy, push access, an
  `acl` that is `internal` or one of the caller's teams, CODEOWNERS and lint. Where CODEOWNERS routes a directory by
  file name (`/knowledge/runbooks/payments-*` in the example repo), it tries
  `<owner_team>-<slug>-<12 hex>` when CODEOWNERS gives the plain name to another team. The `draft-runbook` skill now calls it, instead of git and `gh`.
- **`propose_edit` takes `append`**: it adds to the end of the page as it is on the
  default branch, so a change merged in the meantime isn't overwritten.

## For people: the web app and the extension

- **`docsworth serve`** runs the same MCP server over HTTP on `127.0.0.1:4747`. Nothing is
  hosted.
  - **Requests:** every one must name the server in `Host`. A browser's `Origin` must be
    the server itself, or an extension you allow with `--allow-extension <id>`.
  - **The token:** `/mcp` needs a bearer token, kept in your state directory and shown with
    `--print-token`.
  - **Each tab gets its own session,** so what a tab has shown decides what it may write. A
    tab whose session is lost stops, rather than carrying on in a fresh one.
- **The web app**, at `/`: an overview, search, pages, teams, the link graph, capture and
  settings. Pages render as safe markdown. Images become links, so nothing is fetched. A
  link to another page opens it only if you can see that page. Outside links stay links
  only for http, https and mailto.
- **The browser extension** (Chromium, Manifest V3, Chrome 130 or later). You build it from
  `packages/extension` and load it unpacked; it isn't in a store.
  - **What it adds:** a side panel to search, read and draft; "Save selection to Docsworth"
    from any page; and, in Gmail, a button beside an open thread that drafts from it when
    you click.
  - **The token** stays in the extension's session storage, which content scripts can't
    read.
  - **Nothing is written** until you open the draft PR.

## Reading more sources

- **Mirror view** (off by default, `mirror.serve`). Mirrored Confluence and Notion pages
  reach agents as context they can read but never cite, under the same ACLs as other
  pages.

## Production

- **GitHub outages and limits.** Reads retry what passes: no answer in 30 s, a 5xx, or a
  rate limit GitHub says lifts within 10 s. Writes never retry. A rate limit is named as
  one, with when it lifts.
- **Supply chain.** CI runs the suite, a production-dependency audit, a clean install
  from the packed tarball and a CycloneDX SBOM on every PR. Every action is pinned by
  commit SHA. Releases are published from CI with npm provenance, and the SBOM is
  attached to the GitHub release.
- **Hostile pages.** A page or wiki page built to be slow costs about what prose of the
  same size does: link parsing, the redaction sweep and Confluence conversion are linear
  on unclosed tags, comments and quotes. Frontmatter over 16 KB is refused before YAML
  reads it. A Confluence page nested too deep to convert is mirrored as escaped plain
  text instead of ending the run.
- **Security policy.** `SECURITY.md` sets out how to report a vulnerability and what's in
  scope. `docs/enterprise/` holds pre-filled answers for a security questionnaire.

## Packaging

- Published as `@docsworth/cli`, with the command `docsworth` (the project was agent-kb).
  The package carries the web app. It doesn't carry the extension.
- **The plugin launcher keeps the repo off the command line.** It passes the repo in
  `DOCSWORTH_KNOWLEDGE_DIR`. On Windows it quotes each word, and refuses a `DOCSWORTH_BIN`
  that `cmd.exe` would expand or split. `npx` runs from your home directory, so a
  project's `.npmrc` can't send `@docsworth` to another registry.
- The paid tier (mirror connectors, digest, reports, the SIEM sink, the benchmark) is a
  separate package, `@docsworth-pro/pro`, installed beside the CLI, globally or in the same
  project. Nothing of it is in the public package. The CLI finds it by name, and refuses
  one built for another version of the contract between the two (its host API), naming
  both versions. Without it, each paid command exits 2 with `<feature> is part of
  Docsworth pro, which isn't installed`, and a config that requires the paid HTTP audit
  sink refuses to start.
- To use the paid tier through the Claude Code plugin, set `DOCSWORTH_BIN` to the absolute
  path of a CLI installed beside pro. For a global install on macOS or Linux, that's
  `$(npm prefix -g)/bin/docsworth`. Without it, the plugin runs the CLI through `npx`,
  which can't see a separately installed pro.
- `docsworth bench run` (paid tier) exits 2 when every run fails, as with no credentials,
  a bad key or a bad base URL. For an API error it prints only the HTTP status, never the
  server's text; the full error is in the run's `runs.jsonl`. `bench score` on a directory
  with no `grading.csv` says to score a `bench run`'s results directory.

## Not verified against the real thing

These were tested against fakes only: an org that enforces SAML SSO, fine-grained
tokens, GitHub team permission calls, ruleset bypass actors, and GitHub Enterprise
Server. The launcher's Windows command line was checked as Node hands it to `cmd.exe`,
not on Windows itself.
